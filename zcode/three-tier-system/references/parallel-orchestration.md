# 多写调度协议

仅在准备第二个 `WRITE`、维护多条写入线或恢复多写现场时读取；活动写入数为 `0|1` 时不加载。

## 1. 第二写入判定

必须同时满足：

1. 两包位于同一可运行前沿。
2. 排他写集合不相交；同一大文件默认不可拆。
3. 共享契约、状态模型、锁文件和构建配置已冻结。
4. 各包可形成独立 candidate、验收结论和失败边界。
5. 重型测试、设备、依赖/缓存和集成目标已有串行顺序。
6. 验收位有容量，且父会话终止时磁盘检查点足以恢复。
7. 可重叠实现时间大于协调、冲突和组合验证成本。

任一项不满足即保持单写。接口未稳定时先串行完成并集成接口棒，再向下游扇出。

## 2. lane、租约与资源

每包登记 lane、独立 worktree/分支、前置依赖、契约版本、读集合、排他写集合、base/candidate、证据失效条件、资源槽和集成顺序。需要越出租约时停止；转移租约前确认旧员工及派生进程停止并固定现场。

16G Flutter 类项目的保守容量：

| 资源 | 容量 |
|---|---:|
| 并行写入包 | 2 |
| Flutter/Gradle/重型测试 | 1 |
| 模拟器或真机 | 1 |
| 依赖解析、锁文件、缓存配置 | 1 |
| 集成目标 | 1 |
| 待验收 candidate | 1 |

容量仅凭机器实测提高。资源槽由经理授予；每个令牌代表已分配的容量单元，容量大于 1 时使用 `test#1`、`test#2`。验收位满时不派新写入棒，但可继续独立 `READ`。

优先顺序：多个只读调查 → 一写一读 → 验证等待时准备只读证据 → 两个写入员工。不得把只读准备升级成未授权写入。

## 3. 证据失效

“零引用/无调用方/可删除”等否定性证据必须绑定冻结快照和搜索域；每个 `READ` 独占 worktree 外证据文件。可能新增引用的候选会使证据 `STALE`；删除、迁移或清理须在相关线集成后于当前组合版本重查。

员工证据只证明其 candidate。契约、相关文件、依赖、环境或组合状态变化后，只复用经核对仍有效的部分。

## 4. 事件驱动监督

不启动常驻巡航、轮询脚本或后台终端。经理依靠员工完成/阻断通知、有界状态检查和磁盘事实管理 lane：

- 每次派发、租约/资源变化、candidate 入队和异常事件后更新指导文档。
- 状态检查只判断是否有新差异、新证据、阻断或结果不明；超时本身不构成结论。
- 一条 lane 异常时冻结该 lane 的新写入，先核对 worktree、HEAD、进程和实际差异；不影响证据仍有效的其他 lane。
- 结果不明的写入域对账前不得重派或转移租约。

## 5. 验收、集成与恢复

1. 员工固定 candidate 后停止写入，进入 `READY_FOR_MANAGER_REVIEW`。
2. 经理核对 base/candidate、diff、租约、资源和证据绑定。
3. 通过后进入 `QUEUED_FOR_INTEGRATION`，按依赖拓扑排序。
4. 集成前复核目标 HEAD、契约和否定性证据。
5. 单一集成执行者合入；冲突或目标变化即停止。
6. 组合状态只补会改变放行判断的最小验证。

低耦合 candidate 可小批集成；失败先缩小受影响批次。基线对照只用于区分历史失败、环境波动、缓存污染或证据矛盾。

新经理会话把旧 agentId 视为失效，从指导文档核对 worktree、HEAD、未提交差异、遗留进程和 candidate。任何身份或结果无法确认的 lane 保持冻结，直到磁盘事实完成对账。
