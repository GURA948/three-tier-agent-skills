# 经理动作卡

只读当前动作小节。任务包字段见 `employee-brief.md`，多写调度见 `parallel-orchestration.md`。

## 1. 运行中纠偏

```text
指令：CONTROL-<n>
身份：<包/lane/尝试/规格/candidate 前状态>
取代：<旧指令；无则 NONE>
继续允许 / 立即停止新增：<准确范围>
保留并报告：<改动、进程、未明结果>
停止条件：<何时交回>
```

触及规模线时先停新增并逐文件映射验收编号。经理读盘后决定保留、收缩或撤回；不让员工为“整洁”删除现场。

## 2. 审查退回

一次列清固定 candidate 的全部已证实阻断，不夹带邻接改进。

```text
指令：REVIEW_RETURN-<n>
绑定 candidate：<完整提交或明确未提交状态>
阻断项：<文件/行为/证据 → 验收编号>
只允许修：<最小范围>
复用证据 / 需补验证：<仍有效项；命令与判定>
新 candidate / 停止条件：<要求>
```

candidate、规格或契约变化后，先判断证据失效范围。

## 3. 续派与换人

续派须等上一轮结束，并携带包类型、活动写入数、身份和唯一下一动作；换人前确认旧员工及派生进程停止，固定 worktree/HEAD/未提交现场。新员工第一步只读对账。

```text
指令：CONTINUE-<n> | HANDOFF-<n>
当前事实：<目录/HEAD/工作区/candidate/进程>
已完成且不重做：<列表>
仅剩缺口：<唯一动作>
租约与资源变化 / 证据失效：<无则 NONE>
停止条件：READY_FOR_MANAGER_REVIEW | BLOCKED
```

## 4. 资源槽

```text
RESOURCE-GRANT <slot> → <包/lane>
允许命令/设备：<范围>
开始条件：<旧持有者已释放>
结束条件：<进程退出 + 原始结果落盘>
禁止：<缓存覆盖、第二份依赖目录、额外后台绕行>
```

令牌代表实际容量单元（如 `test#1`、`test#2`）；指导文档只登记已授予令牌。释放以进程和结果为准。验收等待位满时不派新写入棒，只允许独立 `READ`。

## 5. 中止与恢复

普通补充用 `SendMessage` 排队；仅持续损害、明确方向错误的长命令、重复空转或无法安全收口时强制中止。

1. 记录员工、命令、包、尝试和规格。
2. 中止后核对员工与派生进程；回执矛盾按仍在运行处理。
3. 读取分支、HEAD、未提交/未跟踪、日志、外部状态和遗留进程。
4. 分类为已完成、未完成、未知、越界；未知消除前不重试。
5. 原员工可恢复才续派；否则新员工先只读接手。

父会话恢复时旧 agentId 全部失效。核对 worktree、HEAD、未提交差异、遗留进程、结果和日志；未知结果对账前不得续派写入。

## 6. 经理验收

- 身份：目录、分支、起始 HEAD、candidate、工作区、未跟踪、提交归属。
- 范围：逐文件对应验收编号；新增、删除、文件数合理。
- 并行：依赖、契约、写租约、其他 lane、资源、证据失效一致。
- 行为：成功、失败、恢复、重复和部分成功路径。
- 证据：真实命令、目录、退出状态、原始输出、绑定版本；未运行标 `NOT_TESTED`。
- `READ`：冻结快照、起止校验、搜索域、独占证据文件；相关变化后在组合版本重查。
- 监督：员工事件、经理检查与无法确认的时段均有记录。
- 范围控制：无临时脚手架、顺手重构或未知归属清理。

结论只选 `REVIEW_PASSED | REVIEW_RETURN | BLOCKED`。实质代码变更在同次验收做一次对抗式自审，不开启无限复查。只有会改变用户结果的取舍才交用户决定，并说明选项、影响、建议与默认后果。

## 7. 串行集成

仅 `REVIEW_PASSED` 的固定 candidate 入队；一次一个集成执行者。

```text
指令：INTEGRATE-<n>
源 candidate：<完整哈希>
目标目录/分支与预期 HEAD：<值>
依赖顺序 / 契约版本：<列表>
允许方式：<cherry-pick/merge/其他>
禁止：<自行解冲突、扩范围、重写历史>
停止条件：目标变化、冲突、证据失效或结果不明即 BLOCKED
回报：实际目标 HEAD、命令、退出状态、组合差异
```

合入后只跑会改变放行判断的最小组合验证。低耦合 candidate 可小批集成；失败先缩小受影响批次。
