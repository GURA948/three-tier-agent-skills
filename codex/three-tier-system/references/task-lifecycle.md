# Codex 任务生命周期

只在创建/复用员工、选择回报路径、恢复、中断、集成或收尾时读取对应章节。本协议不提供系统层巡航门或后台轮询。

## 入口与回报路径

创建前核对当前宿主实际能力：独立任务与 Git worktree、经理读取/等待/发消息/中断、员工主动上报、共享指导文档访问，以及所需权限和审批。把结果写入指导文档，不从技能文案推断。

按以下顺序选择入口：

1. 独立任务 + 主动任务间上报。
2. 独立任务 + 经理有界等待/读取；经理回合结束后不宣称会自动醒来。
3. 用户已授权且宿主支持的临时 heartbeat；只唤醒经理核对，不续派或判定通过。
4. 用户接受能力下降后的单个会话内子 agent。
5. 均不可用则 `BLOCKED`。

子 agent 只做 `READ` 或固定 candidate 的复核，不修改源码、仓库状态或指导文档。

## 创建、复用与回报

创建前列出项目并核对项目 ID、Git 状态、环境和起点。Git 默认使用独立 worktree。记录员工任务/host、目录、分支、起始提交和工作区；首轮提示词使用 [operating-templates.md](operating-templates.md)，写明经理回报目标和预检结果。创建是异步动作，返回后用有界等待确认实际状态。

同一连续阶段复用员工。换人前先形成固定 candidate 或明确 WIP，并核对现场。

主动上报可用时，员工在自己的任务保留报告，同时向经理发送相同精简状态；不可用时记录实际降级入口。员工报告不是验收，经理仍须核对任务和磁盘。

有界等待超时只表示本次等待结束；没有新事件时不重复读取完整历史。用户消息结束等待时先处理用户意图。

临时 heartbeat 必须记录 ID、绑定的员工/工作包/尝试/规格、频率、失效条件和清理责任。它只核对状态，未变化时保持安静；交付、阻塞、换人、规格变化、取消或完成后立即暂停或删除。不同 Codex 客户端能力可能不同，未验证项写 `NOT_AVAILABLE` 或 `NOT_TESTED`。

## 中断、换人与恢复

普通纠偏优先发送后续消息。只有持续损害、明显错误的长命令、重复空转或无法安全收口时才强制中断：

1. 记录员工、工作包、尝试、规格和已知命令。
2. 中断后核对员工与派生进程；矛盾回执按仍可能运行处理。
3. 核对目录、HEAD、未提交/未跟踪、日志和外部状态，将结果分为已完成、未完成、未知、越界。
4. 未知消除前不重试或另派写入者；原员工能恢复就优先续派，否则新员工先只读对账。

上下文压缩后，从指导文档恢复当前状态、最近决定和下一动作，不从聊天摘要重建已落盘细节。

应用重启或经理任务更换时：从指导文档取得员工、worktree、candidate、旧经理和监督机制；用任务工具确认员工真实状态；核对 HEAD、差异、进程和目标分支；写入新经理 ID并更新员工回报目标；清理过期 heartbeat。结果不明的写入域对账前不得创建第二个写入员工。

## 审查退回与集成

审查退回默认发给原员工，绑定固定 candidate，只允许关闭当前已证实阻断的最小范围。新 candidate 只重查新增差异及受影响证据。

`REVIEW_PASSED` 后，使用运行模板建立集成授权：准确源 candidate、目标目录/分支和预期 HEAD、依赖顺序、允许方式、唯一执行者、停止条件与回报字段。

经理仅在机械集成已获授权、现场清楚且不会演变为实现工作时直接执行；否则交给原员工或项目规定的集成者作为独立 `WRITE`。目标变化、冲突、证据失效或结果不明即 `BLOCKED`，不得自行改变业务语义。目标确认包含 candidate 后写 `INTEGRATED`，再做最低成本最终验收。

## 收尾

写 `DONE` 前确认：员工无未决写入或请求；临时 heartbeat/自动化已清理；遗留命令、审批、未明结果和迟到消息已处理；worktree、分支和未提交状态已记录；最终目标 HEAD、验证层级、`NOT_TESTED` 和剩余风险已写入指导文档。删除或归档仍需用户/项目授权。

完成后到达的旧报告或过期事件只作历史证据，不自动重启工作。
